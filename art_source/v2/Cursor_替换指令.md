# Cursor 美术替换指令

请直接在当前 unwept 项目实施本素材包接入。先阅读仓库设计文档、docs/PROGRESS.md、docs/MISSING_ASSETS.md、docs/CHARACTER_ART.md 和 src/game/layout.ts。保留现有故事、证据条件、存档兼容与试玩结尾范围。

## 素材状态与处理要求
这是14张新绘源图，不是已经裁好的生产资源；manifest.json列出真实尺寸。人物、道具、UI虽有alpha通道，但部分仍带柔边底色或光晕，须在浅色和深色底分别检查。不得直接整张贴进游戏，也不得把规则网格裁切当成已对齐动画。

1. 将原图保存到独立美术源目录，输出裁好图到 public/art/v2/，旧图保留以便回退。先制作接入清单，随后直接执行，不停在方案。
2. 人物逐个裁切，保留抗锯齿，清除背景光晕；统一脚底锚点、成人身高、儿童比例、头身比例。不要非等比拉伸。小满动作图4列3行：第一行空手站立/三步，第二行端碗站立/三步，第三行提箱站立/三步。所有步行帧须逐帧核对，生成动作的步态不保证天然无缝。使用已画在手上的碗和箱时关闭程序重复道具，防止悬浮碗及双箱。
3. cast_6从左到右：小满、桂芬、杜长贵、谷建军、谷雨、余婆。余婆不等于谷秀兰，不得将两人混用。portraits上排为小满四表情，下排桂芬/长贵/建军/谷雨。特殊动作表须核对服装差异并统一后接入；建军图把钥匙露出来了，若剧情只允许隔衣按钥匙，就修正或沿用其他站姿，不改剧情迁就图片。
4. 四处长背景真实尺寸均为2172×724，不能直接非等比拉到5200×1080。按原宽高比例、裁切与合理分段铺设适配，保留清晰度；需要延展或分层的部分明确标记待补画。库边世界5200×1080，村口4000×1080，灵堂3600×1080，街道4600×1080；脚底基线y=800。必须让路面、窗、门、倒桩等热点与画面对应，不能让人踩空或站进水里。
5. 道具表按实际内容裁切，不依靠每格尺寸强切。近景表切成独立图；水纹、被角呼吸、火星与灯光动画分别实现。使用静水底图叠加水纹，不以文字直接提前给出谜底。十九条旧布数量须实际核对；数量不符时使用单条布独立排列成19条，不能沿用错误数量。遗像仅按剧本确认角色后使用，图片本身不能证明人物身份。
6. UI图只提取底板纹理和边框；文字、数字、按钮交互仍用代码，保留可读性、适配性及正常/悬停/禁用状态。对白保持底部，半身像在对白框上方，不遮挡谜题。
7. 标题和开场用各自背景。开场记忆→库边→村口保持同一色调。不得将效果图误称为已分层原画；当前背景都是合成平面图。
8. 检查移动、转身、端碗、提箱、提灯、放碗与停步的状态切换。近看关闭恢复操作；过场锁定时不显示可操作假提示。清理提示重叠。

## 验收
运行 npm test 与 npm run build。实际浏览器从新游戏验证：取碗→鞋印与倒桩观察→村口→孝布→证词起腔→借灯→街窗比较→试玩结束；验证中途刷新继续、旧档、静音、减少动态、误选重试。无法实测的项目如实标明。
更新 docs/ART_REPLACEMENT.md 列出原图到输出图映射、裁切坐标、尺寸、锚点、接入位置、仍缺素材与已知问题。完成本地预览后提交推送，按已有Pages流程更新线上；检查部署资源404和控制台异常，并给出试玩地址。不要删除剧情或自动解锁证据来通过验收。
